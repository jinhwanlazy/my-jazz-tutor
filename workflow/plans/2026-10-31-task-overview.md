# 과제 특성과 개인 예상 부담을 우선하는 표시

상태: 구현·검증·실행 앱 적용 완료
대상: workflow 0.4.2 / 기존 practice 기록의 표시

## 요청과 범위

목록·연습실·과거 기록에서 과제 특성과 개인 예상 부담을 먼저 표시한다. 낮음/보통/높음, 숫자 단계, 단계 비교 이유는 화면에서 숨긴다. 기존 과제에도 같은 표시를 적용한다. 원래 과제 조건·평가·예상·피드백·MIDI는 덮어쓰지 않는다. 당시 예상이 없으면 저장된 예상이 없음을 명시한다.

내부 비교 척도는 끝이 정해진 세 등급 대신 추가 기준 예제로 확장하는 순서 척도로 명시한다. 새 rubric v2는 양의 정수 단계를 사용하고 등록된 같은 축의 기준 예제를 반드시 요구한다. 존재하지 않는 상위 단계를 만들어 내지 않는다. 기존 rubric v1 자료는 별도 정의로 계속 검증한다. 악보/과제 schema 1·2와 번역 형식은 유지한다.

## 재사용과 책임

- `notation.score_for`로 당시 과제 자체에서 읽을 수 있는 특성을 계산한다. 기존 `difficulty.score_features`의 저장된 사실과 관측 의미는 변경하지 않는다.
- `webapp.display_target`이 새 표시용 요약을 붙인다. 원장이나 번역 캐시에 소급 값을 쓰지 않는다. 과거·현재 과제 모두 같은 함수와 UI를 사용한다.
- 개인 예상은 기존 `difficulty.prediction`을 표시한다. 단계 이유는 숨기되 원본을 보존해 이전 번역 캐시·추천 맥락·이력 호환성을 유지한다.
- 새 rubric과 이전 rubric을 버전으로 구분하고 스키마의 고정 1/2/3 제한을 없앤다. 숫자의 합산·동일 간격·최고 등급 의미는 부여하지 않는다.

## 실행과 검증

1. DESIGN·COACH·사용 안내에 표시와 버전 계약을 반영한다.
2. 특성 요약·UI·번역을 구현하고 단계가 화면에서 사라지는지 확인한다.
3. 기존/새 rubric 검증과 확장 사례를 테스트한다. 같은 축의 실제 등록 기준 없이 새 숫자를 허용하지 않는지 확인한다.
4. 합성 과제의 현재/과거/단계 없는 기록·음원 없는 과제·즉흥 지시·번역·원본 불변을 단위/브라우저에서 검증한다.
5. Python 전체 테스트, 커리큘럼 검사, Node 테스트와 Chrome 브라우저 검사를 실행한다. Node는 작업 영역의 가상환경에서 실행한다.
6. 검증한 소스를 새 버전으로 커밋/태그하고 기존 publication 경로로 활성화한다. 활성 버전·기존 기록/세션의 불변·과거 화면 적용을 직접 확인한다. 실제 사용자 데이터로 테스트 과제나 피드백을 생성하지 않는다.

## 결과

- 목록·연습실·과거 상세에 특성과 출제 당시 개인 예상 부담을 우선 표시한다.
  단계/기준 비교는 숨기고 예상이 없던 과제에는 ‘저장된 예상 없음’을 표시한다.
- task-demands-v2의 순서 척도와 v1 아카이브를 구현했다. 등록된 기준을 추가하는
  합성 확장 사례와 미등록/잘못된 숫자 거부, 원본 평가 불변을 검증했다.
- `uv run python -m unittest discover -s tests -v`: 165개 통과.
- `uv run python review.py validate-curriculum`: 0.4.2, 예제 6개·마일스톤 6개 유효.
- 전용 Node 환경에서 capture/i18n/score 테스트 14개 통과.
- Chrome 브라우저 통합 검사 통과: 새 과제의 앞쪽 요약, 한/영·모바일 화면,
  schema 1 및 rubric v1 과거 상세, 단계 비표시, 원장·세션 불변을 확인했다.
  기존 생성/번역 실패 복구·피드백·녹음·반복 회귀도 함께 통과했다.
- 실제 음악 난도 척도나 개인 예상 정확성을 경험적으로 검증한 것은 아니다.
  새로운 상위 음악 기준을 임의로 만들지 않았으며 구조만 확장 가능하게 변경했다.
- `v0.4.2`를 기존 publication 경로로 활성화하고 실행 서버를 재시작했다.
  호환 미완료 과제를 유지했고 업데이트로 종료된 과제는 없다.
- 활성 앱의 기존 과제 전체 목록·과거 상세·현재 연습실을 Chrome에서 확인했다.
  한국어 특성/출제 당시 개인 예상, 단계 비표시와 데스크톱·모바일 너비를 확인했다.
  확인 중 서버 쓰기 요청이나 새 사용자 과제/연습 결과는 발생하지 않았다.
- 실제 원장 유효성 검사 통과. 적용 전후 및 화면 확인 후 원장·프로필·보고서·예상/
  번역 자료의 파일 해시와 세션 DB의 논리 내용 해시가 같아 원본 기록과 MIDI 불변을 확인했다.

## 검증 중 조정

새 지침을 포함한 입력 크기가 늘면서 기존 관련 메모 검색 회귀 테스트가 실패했다.
최근 8개를 먼저 채우던 순서가 요청과 관련된 과거 메모를 밀어내는 원인이었다.
입력 한도를 늘리거나 테스트 기대를 낮추지 않고 최근/관련 과제를 번갈아 검토하도록
입력 정책을 v2로 변경한다. 같은 회귀 테스트와 장기 기록 입력 한도 검사를 다시 실행한다.
