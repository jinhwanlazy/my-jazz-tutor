# 설계 결정 — 0.4.3

## 추천의 역할

LLM이 실제 프로필, 과제 조건, 완료 기록, 난이도 라벨, 원문 메모, 스킵 사유를 검토하고
지금 적절한 연습을 구성한다. E01–E06와 기존 커리큘럼은 예시 자료일 뿐 후보 목록이나
필수 진도표가 아니다. 고정 선행 조건, 라벨별 BPM 증감, 고정 목표의 완료율로 추천하지
않는다. 기존 규칙 추천은 과거 동작의 호환 테스트용 코드에 남지만 웹·CLI 추천 경로는
사용하지 않는다. 과거 상세 자기보고의 평가는 그 당시 조건으로 보존한다.

## 실행 경계

서버 바인딩은 기본 `127.0.0.1`이며, `serve --host`에 로컬 IPv4 주소나 `0.0.0.0`을
명시하면 LAN 접속을 허용한다. `localhost` 외 호스트명과 IPv6는 지원하지 않는다.
Host는 실제 연결이 도달한 로컬 IP와 포트에, Origin은 해당 요청 Host에 맞아야 하며
쓰기에는 기존 CSRF 토큰이 필요하다. 와일드카드 바인딩에서도 임의 DNS 이름을 허용하지
않는다. 인증 기능은 없으므로 접속 가능한 기기가 기록과 추천 기능을 공유한다.
HTTP LAN에서도 과제·세션 ID는 `crypto.getRandomValues()`로 생성하고 메트로놈과
저장을 지원한다. Web MIDI는 보안 컨텍스트가 필요하며 일반 LAN HTTP에서는 그 제한을
표시한다. 서버 자체의 TLS나 방화벽 자동 설정은 제공하지 않는다.

표준 라이브러리 로컬 서버가 `codex exec --sandbox read-only --ephemeral --json
--output-schema ...`를 실행한다. 기존 CLI 인증을 재사용하며 별도 API_KEY가 필수는
아니다. 실제 생성에는 Codex 설치·로그인·서비스 연결·사용 가능 한도가 필요하다.
`--ignore-user-config --ignore-rules`와 도구 기능 비활성화, 빈 임시 작업 디렉터리를 쓴다.
원장과 소스는 Codex의 쓰기 대상이 아니다. 사용자 메모는 데이터로 취급한다.

매 요청에 명시적인 맥락을 전달하며 대화 세션을 재사용하지 않는다. 최근 최대 8개 과제와
관련/정정된 과거 최대 4개 과제의 압축 조건, 완료, 최신 피드백/메모 발췌, 스킵/종료,
최근 세션 최대 3건의 측정 요약, 전체 기록의 사실 요약과 생략 범위를 포함한다.
입력 한도가 가까우면 최근 과제와 관련/정정된 과거 과제를 번갈아 검토해 최근 기록만으로
공간을 소진하지 않는다. 생략된 원본 기록은 그대로 보존한다.
프롬프트+출력 스키마의 UTF-8 크기를 64,000바이트 이내로 제한하고 필요하면 과제별
설명 발췌 길이와 사례 수를 줄인다. 텍스트의 보수적인 토큰 상한이며 정확한 토큰 수나
CLI 전체 사용량은 아니다. 필수 프로필·요청·지침만으로 넘으면 명시적으로 실패한다.
원본 MIDI와 전체 악보를 전달하지 않으며 원본 기록은 변경하지 않는다. 이전 모델 해석은
요약 사실에 섞지 않는다. 요약/발췌는 정정된 원장에서 다시 만들고 요청 artifact에 저장한다.
검색은 요청 문구·조성·주요 축·정정 시점을 사용한다. 의미 검색이나 전역 능력 추정은 없다.
입력 크기는 제한되지만 로컬 원장 읽기는 전체 스캔이다.
개인 자료는 Git에 넣지 않지만 추천에 제공한 맥락은 사용자의 Codex 인증 경로로 전송된다.

구조화 결과는 근거 source_ids + 해석/확신, 미확인 사항, 목적/선택 이유, 실제 수행할
조건과 순서, 필요한 악보, 선택적 코드 반주다. 앱이 JSON 필드·출처 ID·음역·마디 수·
박의 연속성과 총합·쉼표·반주 일치 등을 검증한다. 음악적 적합성이나 자연어와 악보의
의미적 일치를 완벽히 인증하는 검사는 아니다. 새 과제는 G- ID, 시도는 T- ID를 받는다.

악보 v1은 4/4의 1–16마디, 손별 한 성부와 화음, 온/2분/4분/8분음표 및 쉼표,
A0–C8과 단일 #/b를 지원한다. 타이·잇단음표·점음표는 지원하지 않는다. 자유 즉흥
등 고정 악보가 부적합한 연습은 이유와 구체적 음·리듬 지시를 갖춘 글로 제시한다.
목표 키·BPM은 예시 커리큘럼에 묶이지 않으며 생성 템포 범위는 20–240이다.

추천은 비동기 작업이다. `.recommendations/R-….json`에 입력 맥락, 결과, 상태,
출처와 사용량을 보존한다. 별도 파일 잠금으로 다중 서버의 중복 생성을 막는다.
동일 요청 ID의 재전송은 항목을 중복 생성하지 않는다. 종료 후 재시작 시 저장된
항목으로 복구하거나 중단 오류로 전환한다. 생성하는 사이 기록·프로필·세션 또는
활성 버전이 바뀌면 저장을 거부한다. 로그인·한도·시간 초과·잘못된 출력은 사용자에게
구분해서 표시하며 고정 과제로 대체하지 않는다. 대화형 코칭도 같은 맥락·스키마·검증기와
CSV를 쓰고 `accept-recommendation`으로만 생성 결과를 저장한다.

## 연습 UI

첫 화면은 날짜별 목록이며 내용·상태·결과 라벨·메모·스킵 사유가 보인다. ‘새 연습’은
분석과 생성을 요청하고 진행 상태를 표시한다. 검증된 항목을 추가해도 자동 진입하지
않는다. 사용자가 항목을 직접 열고 연습한다. 현재 미완료 항목은 하나만 허용한다.
‘연습 완료’는 녹음과 측정을 저장하고 목록으로 돌아간다. ‘다음 연습’은 없다.
완료 항목은 기록 상세로 열며 ‘다시 연습’은 별도 항목을 만든다.

목록 카드의 제목·특성·예상·설명은 같은 안쪽 여백을 사용한다. 연습실의 핵심 설명과
특성은 먼저 보이고, 연습 순서·음/코드 진행·추천 근거는 펼쳐 볼 수 있다. 악보가 없는
과제는 글로 된 연주 조건을 처음부터 펼친다. 언어 변경은 사용자가 펼친 상태를 유지한다.
시작·완료·BPM은 악보 위의 한 제어 영역에 두고 좁은 화면에서는 행을 나눈다.
‘악보로 이동’은 실제 MIDI 헤더 높이를 반영해 가려지지 않는 위치로 이동하며 키보드
초점도 옮긴다. 연습 중에도 Practice 메뉴가 현재 영역으로 표시된다.

‘다음 연습에서 다루고 싶은 것’ 입력은 ‘새 연습’ 버튼 바로 위에 두고 목록 필터와
분리한다. 생성 요청을 보내는 순간부터 생성이 끝날 때까지 입력을 숨긴다. 입력이
있으면 생성 상태에서 함께 검토 중임을 표시한다. 성공 시 해당 요청의 입력을 비우고,
실패 시에는 입력 내용을 유지해 수정하거나 재시도할 수 있게 한다.

완료와 피드백은 분리한다. 완료한 항목에서 불가능/도전적이었음/좋은 연습이었음/
너무 쉬워서 의미 없었음 중 라벨 하나와 선택 메모를 남기거나 수정한다. 피드백이 없어도
완료 상태는 유지한다. 넘기기 사유는 선택이며 녹음 중이면 먼저 저장한다. 별도 연습
기록 탭은 목록에 통합하고 진도 화면은 제공하지 않는다. 영어·한국어 UI 전환은 원문과
진행 중 MIDI 수집·미저장 메모를 보존한다. 생성된 설명은 생성 당시 언어를 보존한다.

사이드 메뉴 이름은 Practice(연습)다. MIDI 연결 상태·연결 버튼·입력 선택은 항상
사이드바에 있고 모바일에서는 상단에 유지한다. 연습 녹음을 시작하면 BPM 입력·슬라이더·
증감 버튼과 변경 핸들러를 잠그며 일시정지 후에도 같은 BPM으로 재개한다. 녹음을
끝낸 뒤 새 녹음을 시작하기 전에 다시 선택할 수 있다. 과거의 템포 변경 기록은 보존한다.

새 과제와 LLM 해석 원문은 항상 영어다. context.language는 en으로 고정하고 화면
선호는 display_language로 구분한다. 언어 전환은 과제를 재발급하지 않는다.
다른 언어의 화면에서는 검증된 번역 캐시를 읽고, 없으면 CSRF 보호 POST로 비동기
Codex 번역을 요청한다. GET은 모델을 호출하지 않는다. 워크스페이스별 번역은 하나씩
진행하고 과제 스냅샷 해시·언어별로 `.translations/`에 저장해 반복 시도에서도 재사용한다.
실패는 원문과 재시도 버튼을 표시하며 자동으로 실패 요청을 반복하지 않는다.
하나의 번역 요청 안에서는 검증에 걸린 필드만 최대 한 번 보정 요청한다. 정상 필드는
유지하고, 보정도 실패하면 원문을 보여주며 명시적 재시도를 기다린다. 인증·한도·연결·
시간 초과에는 자동 재호출하지 않는다. 호출마다 시간 제한은 4분이다. 반환된 시도와
필드별 검증 사유는 로컬 번역 artifact에 남겨 재전송 없이 진단할 수 있게 한다.

번역에는 과제·해석의 표시 문자열만 전달하고 사용자 원문 메모나 MIDI를 별도로 보내지
않는다. 앱은 허용된 문자열 필드만 받으며 숫자·음이름·코드 기호는 자리표시자로 보존하고
악보·반주·BPM·키·마디 수·출처 ID·확신은 원문에서 복사한다. 음악 의미의 완전한 일치까지
자동 증명하지는 않는다. 원장·조건 스냅샷은 수정하지 않는다. 과거 한국어 과제도 원래
언어를 원본 생성 기록에서 확인해 표시용 번역만 만든다. 원래 언어를 알 수 없으면
현재 프로필로 추정하지 않고 번역기에 미확인으로 전달한다.
번역 protocol 2는 four bars 같은 명시적 단위가 있는 수량/위치 표현을 입력에서만 숫자로
정규화해 보호한다. 모델에 자리표시자 값도 제공하되 출력은 자리표시자를 유지한다.
8분쉼표·4분 음표 같은 표기는 해당 필드의 영문 음악 용어와 일치하면 허용한다.
기존 정상 캐시는 원래 protocol 1로 검증해 재사용하며 새 번역을 강제하지 않는다.

## 기록과 업데이트

하나의 Git monorepo 안에 workflow(개발)와 practice(실사용)를 둔다. practice.csv는
assigned/completed/reported/corrected/discarded/cancelled/retired 사건을 추가하는
원장이다. 수정은 정정 사건이며 원문을 덮지 않는다. 세션의 원본 MIDI와 재생 사건은
sessions.sqlite3에 보존한다. 조건 스냅샷은 불변이며 예전 기록을 새 설계로 재평가하지
않는다. generated 과제는 자체 스키마 지원 여부로 호환성을 판단하며 커리큘럼 ID와
대조하지 않는다. 기존 과제는 기존 조건 비교를 유지한다.

Git 커밋·태그가 버전 이력이다. publish는 선택한 스냅샷을 캐시하고 새 버전을 우선
활성화한다. 호환 미완료 과제는 원래 조건 그대로 이어가며 비호환 과제만 사유와 함께
retired로 종료한다. 완료 기록·메모·MIDI는 유지한다. 종료는 실패·스킵·실적이 아니다.
.runtime은 폐기 가능한 캐시이며 runtime.json 핀과 개인 자료·추천 맥락은 Git 제외다.
테스트는 임시 디렉터리와 합성 자료만 사용한다. 실제 Codex 연결 테스트도 합성 자료다.

## 사실과 해석

라벨은 주관적 난이도다. 완료·쉬움·MIDI 입력은 음/박/무중단/숙련도 통과 증거가 아니다.
BPM은 메트로놈 설정이며 분석된 실제 연주 BPM으로 표현하지 않는다. 관측과 LLM의
해석을 별도로 보여준다. 없는 관측은 미확인이고 실패나 0점이 아니다. 당일 결과,
후일 재현, 전이는 다르며 전체 재즈 숙련도 백분율을 만들지 않는다. 생성 과제의
기준은 연습 목적이지 자동 점수가 아니다. MIDI 음악 분석은 후속 작업이다.

## 과제 난이도와 개인 예상

목록·연습실·기록 상세는 과제 특성과 생성 당시의 개인 예상 부담을 먼저 표시한다.
특성은 원래 악보에서 읽을 수 있는 엇박·쉼표·반복되는 왼손 리듬·동시음·양손의 다른
진입 등이며 실제 수행이나 개인 능력을 추정하지 않는다. 숫자 단계, 낮음/보통/높음,
단계별 비교 이유는 화면에서 표시하지 않는다. 내부 등급으로 카드의 색·순서를 정하지 않는다.

표시 변경은 기존 기록에도 적용한다. 조회 시 당시 과제로 요약을 만들며 원장·원본 평가·
예상·번역 캐시를 수정하지 않는다. 악보가 없으면 글로 명시된 조건을 제공하고 악보 특성을
만들지 않는다. 자유 즉흥의 허용 음을 실제 동시 화음이나 정해진 리듬으로 집계하지 않는다.
과거에 개인 예상이 없었던 과제는 저장된 예상이 없음을 표시한다. 지금의 피드백을 이용해
당시 예상을 소급 생성하지 않는다. 예상이 있는 경우 원래 값·근거·불확실성을 유지한다.

schema_version 2는 일곱 내부 비교 축과 예상을 보존한다. 새 task-demands-v2는 상한을
고정하지 않는 순서 척도이며 초기 예제 1~3은 전체 음악의 낮음/보통/높음 등급이 아니다.
숫자는 같은 축에서 등록된 기준 예제에 연결되어야 한다. 기준을 확장하면 새 rubric 버전으로
추가하며 기존 snapshot은 해당 버전으로 검증한다. 현재 기준으로 평가할 수 없는 항목은
out_of_range와 null level을 사용하며 임의의 상위 숫자를 생성하지 않는다. v1 정의와 기존
schema 1·2 자료도 그대로 지원한다. 축의 합산·동일 간격·보편적 음악 등급을 의미하지 않는다.

예상 부담과 실제 최신 라벨은 다음 추천의 맥락으로 제공한다. good을 중간 난도 점수로
해석하지 않으며 전체 라벨만으로 원인 축이나 숙련도를 판정하지 않는다. 자동 BPM 증감이나
능력 업데이트는 없다. 명시적 반복의 기존 예상은 새 예측 통계에서 제외한다. 앱의 검사는
표현·출처·악보의 일관성 검사이며 LLM 평가의 음악적 타당성이나 실증적 보정을 증명하지 않는다.

## 재생, 악보와 MIDI 보존

Web Audio의 오디오 시계로 메트로놈과 선택적 코드 패드를 예약한다. 녹음 시작 BPM을
유지하고 실제 설정을 저장한다. 과거 녹음의 템포 변경 이력도 읽는다. 일시정지 후 재개는
첫 마디부터다. 탭 숨김·오디오 중단은 재생을 멈추고, MIDI 수집은 세션 종료 전까지
유지한다. 패드 출력을 입력 MIDI에 합성하지 않는다. SysEx 권한은 요구하지 않는다.

3초마다 IndexedDB에 먼저 청크를 보관하고 서버에 전송한다. 세션 ID와 순서로 중복을
구분하고 서버 확인 후에만 로컬 청크를 지운다. 강제 종료 시 마지막 체크포인트 이후
입력은 손실될 수 있다. 복구된 중단 세션을 완전한 기록으로 표시하지 않는다.
MIDI 구간은 첫 Note On부터 마지막 Note Off/해당 서스테인 해제까지며 중간 쉼도 포함한다.
불완전한 입력이면 미확인이다. 정상 종료한 세션은 일시정지를 뺀 재생 시간을 대안으로
쓴다. 연습일은 프로필 시간대로 세션별 분배한다. 원본은 자르지 않는다.

악보는 과제 자체의 음 데이터로 그리며 패드 보이싱과 구분한다. 악보 전체를 하나의
수평 시간축에 놓고 오디오 시계로 커서·입력 흔적·스크롤을 연속 이동한다. Bravura를
번들하며 악보 라이브러리나 네트워크는 렌더링에 필요 없다. 온음표/2분음표 머리는
속이 투명하다. 라이브 흔적은 키를 누른 시점·길이이며 페달 sustain이나 정확도 판정이
아니다. 손 구분은 과제 음역을 사용하며 실제 손 감지가 아니다. 기기 지연이 존재할
수 있다. 라이브 버퍼는 현재 패스의 표시일 뿐 원본 녹음이나 재생 형식의 대체가 아니다.
악보 크기는 CSP가 차단하는 인라인 style 대신 SVG width/height 속성으로 설정한다.
화면 폭에 따른 축소는 같은 비율을 사용하므로 마디 수가 음표 크기를 바꾸지 않는다.
짧은 악보를 화면 끝까지 늘리거나 긴 악보를 압축하지 않는다. 창 크기가 바뀌어도
악보·커서·MIDI 흔적은 같은 시간축을 유지한다.
