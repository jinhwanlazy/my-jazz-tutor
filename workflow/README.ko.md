# 워크플로 개발

[English](README.md) · [한국어](README.ko.md)

`workflow/`는 코칭 지침·프로그램·발행을 개발하는 영역이고 실제 연습은 `../practice/`에
있습니다. Git 저장소는 상위 루트 하나입니다. 역할별 AGENTS.md를 먼저 읽습니다.

## 0.3.0 추천과 UI

‘새 연습’은 로컬 Codex CLI가 프로필, 최근 실제 연습, 라벨, 메모, 스킵 사유를 분석해
새 과제를 만드는 요청입니다. E01–E06, 선행 조건, 대표 목표는 필수 진도가 아닙니다.
기존 커리큘럼은 참고 예시로만 제공합니다. 완료/쉬움은 정확도나 숙련도 증거가 아닙니다.

목록이 첫 화면입니다. 생성 상태를 표시하고 검증한 항목을 추가하되 자동 진입하지
않습니다. 항목을 직접 열어 연습하고 ‘연습 완료’로 녹음·측정을 저장한 뒤 목록으로
돌아옵니다. 완료 항목에서 네 가지 난이도 라벨과 선택 메모를 남기거나 수정합니다.
피드백이 없어도 완료이며, 다시 하기는 별도 시도를 만듭니다. 스킵 사유는 선택입니다.
별도 연습 기록 탭과 진도 화면은 없습니다. 메트로놈 BPM은 분석된 실제 연주 BPM이
아니며 MIDI 음악 분석은 아직 구현하지 않았습니다.

## 0.3.2 표시 언어와 연습 제어

사이드 메뉴는 Practice(연습)로 표시합니다. MIDI 상태·연결 버튼·입력 선택을 사이드바에
항상 두고 모바일에서는 상단에 유지합니다. BPM은 시작 전에 선택하며, 녹음이 끝날
때까지 입력·슬라이더·증감 버튼을 잠급니다. 일시정지 중에도 변경할 수 없습니다.

새 과제와 해석 원문은 항상 영어로 생성합니다. `context.language`는 en이며
`display_language`와 CLI `--language`는 화면 선호만 나타냅니다. 한국어 화면에서
과제를 보면 Codex가 제목·설명·손별 역할·음과 리듬 설명·방법·선택 이유·해석·미확인
사항을 번역합니다. 기존 CLI 로그인과 읽기 전용 구조화 출력을 재사용합니다.

과제 원문·메모·MIDI를 수정하지 않고 표시용 번역을 `.translations/`에 별도 저장합니다.
스냅샷·언어별로 재사용하며 워크스페이스에서 하나씩 번역합니다. GET은 모델을 호출하지
않고 화면의 POST 요청이 번역을 시작합니다. 번역 중이나 실패 시 원문을 표시하며
실패는 명시적으로 재시도할 수 있습니다. 악보·반주·BPM·키·출처 ID는 원문 그대로이고
본문의 숫자·음이름·코드 기호도 검증합니다. 음악 의미 전체를 자동 검증하는 것은 아닙니다.
과거 과제도 생성 기록에 있는 원래 언어를 사용해 표시용 번역만 만듭니다.

## Codex 연결

‘다음 연습에서 다루고 싶은 것’은 ‘새 연습’ 버튼 바로 위에 있습니다. 생성 중에는
입력을 숨기고 희망 사항을 함께 검토 중임을 표시합니다. 성공하면 보낸 내용을 비우며,
실패하면 수정·재시도할 수 있도록 그대로 유지합니다. 목록 필터는 그 아래에 둡니다.

`codex --version`, `codex login status`로 설치와 인증을 확인합니다. 필요하면 터미널에서
`codex login`을 실행합니다. 기존 ChatGPT 인증을 재사용하므로 별도 API_KEY는 필수가
아닙니다. 실제 생성에는 네트워크와 Codex 사용 가능 한도가 필요합니다.
`JAZZ_CODEX_BIN`으로 실행 파일을 지정할 수 있습니다.

앱은 빈 임시 디렉터리에서 `codex exec --sandbox read-only --ephemeral --json
--output-schema ...`를 실행하고 사용자 설정·도구·플러그인·셸·위임 기능을 끕니다.
명시적 맥락만 전송하며 기존 대화는 공유되지 않습니다. Codex는 JSON만 반환하고
앱이 출처 ID·필수 조건·음역·박 합계·반주 일치 등을 검증해 저장합니다. 로그인, 한도,
연결, 4분 시간 초과, 잘못된 출력은 별도 오류이며 고정 과제로 대체하지 않습니다.

맥락에는 최근 최대 8개 과제와 관련되거나 정정된 과거 최대 4개 과제, 최신 피드백,
완료/스킵 기록, 측정 요약, 전체 기록의 사실 요약을 담습니다. 요청 문구·조성·주요
난이도 축으로 관련 기록을 찾으며 추천할 과제의 범위를 제한하지 않습니다.
전체 악보 대신 조건 설명과 악보 특징을 전달합니다. 메모가 길면 정확한 발췌와 생략량을
표시하며 원본은 보존합니다. 사실 요약은 정정된 최신 원장에서 다시 계산합니다.
앱이 보내는 프롬프트와 출력 스키마를 합쳐 UTF-8 64,000바이트로 제한합니다. 이는
텍스트 토큰 수를 보수적으로 제한하기 위한 상한이며 정확한 토큰 수나 CLI 전체 사용량은
아닙니다. 필요하면 사례 수와 발췌 길이를 줄이며 필수 프로필·요청만으로 상한을 넘으면
명시적으로 실패합니다. 원본 MIDI는 전송하지 않습니다. 결과와 원래 맥락은
Git에서 제외된 `practice/.recommendations/`에 보존합니다. 생성 중 기록·프로필·세션·
활성 버전이 바뀌면 저장하지 않습니다. 의미적으로 적절한 음악인지까지 완벽히 검증하는
검사기는 아닙니다. 악보는 4/4, 1–16마디, 손별 한 성부와 화음, 온/2분/4분/8분음표와
쉼표를 지원합니다. 타이·잇단음표·점음표는 지원하지 않습니다.

새 과제에는 멜로디·리듬·박자·조성·화성/보이싱·강세/표현·양손 협응의 난이도를
표시합니다. 각 축의 세 단계 기준 예제와 비교하고 이유를 남기며, 불명확/해당 없음/
기준 범위 밖은 별도로 표시합니다. 기준은 경험적으로 검증되기 전의 임시 척도이며
종합 점수나 숙련도 지표가 아닙니다. 목록은 주요 축만, 상세는 전체 평가와 악보 특징을
보여줍니다. 개인 예상 부담은 과제 난이도와 분리해 근거·불확실성과 함께 저장합니다.
다음 추천에서 생성 당시 예상과 최신 피드백을 비교하되 good을 중간 난도로 바꾸거나
전체 피드백 하나로 원인 축을 단정하지 않습니다. 번역은 이유만 바꾸며 평가 값은 보존합니다.
과거 과제에 소급 평가하지 않고, 정정된 피드백이 과거 평가를 덮지 않습니다.

번역은 8분쉼표·4분 음표 같은 정상 표기를 원문 용어에 맞춰 허용하며, four bars 같은
수량 표현도 번역 입력에서 보호합니다. 잘못된 필드만 요청 내에서 한 번 보정하고,
최종 실패하면 원문과 재시도 버튼을 유지합니다. 이전 정상 번역 캐시를 재사용하며
반환된 번역과 검증 사유는 Git에서 제외된 로컬 캐시에 보존합니다.

대화형 코칭도 활성 COACH.md, 같은 기록·스키마·저장 경로를 사용합니다. 저장소 루트에서:

```sh
uv run --project practice jazz recommend
uv run --project practice jazz recommend-context --output /tmp/jazz-context.json
uv run --project practice jazz recommendation-schema
uv run --project practice jazz accept-recommendation --context /tmp/jazz-context.json --input /tmp/jazz-recommendation.json
```

`recommend`와 별칭 `suggest`는 생성 후 목록에 저장합니다. `status`는 읽기만 합니다.
대화형 코치가 직접 분석할 때는 context와 schema를 읽어 JSON을 작성하고 accept로
검증·저장합니다. 원장이나 설치 소스를 직접 고치지 않습니다. `reflection TASK --input`
명령은 웹과 같은 라벨·선택 메모를 받습니다. 기존 상세 보고·정정 명령은 호환용입니다.

## LAN 접속

0.3.1부터 `--host`로 LAN 바인딩을 명시할 수 있습니다. 기본은 `127.0.0.1`입니다.
저장소 루트에서 실행하고 다른 기기에서는 `http://<서버-LAN-IP>:8768`로 접속합니다.

```sh
uv run --project practice jazz serve --host 0.0.0.0 --port 8768 --open
```

`0.0.0.0`은 모든 IPv4 인터페이스이며 특정 로컬 IPv4 주소로 제한할 수도 있습니다.
`localhost`도 지원하지만 다른 호스트명과 IPv6는 지원하지 않습니다. `--open`은 서버
컴퓨터의 브라우저를 엽니다. 방화벽 설정은 바꾸지 않습니다. 로그인 기능은 없으므로
접속 가능한 기기는 개인 기록을 읽고 수정하거나 서버의 Codex 계정으로 추천을 요청할
수 있습니다. 신뢰하는 LAN에서 사용합니다. Host·Origin·CSRF 검사는 유지합니다.

일반 HTTP에서도 생성·메트로놈·저장은 동작합니다. MIDI는 지원 브라우저의 HTTPS 또는
localhost가 필요합니다. 서버 자체는 TLS를 제공하지 않으므로 원격 MIDI는 SSH 포트
전달 후 클라이언트의 localhost로 접속할 수 있습니다. 미전송 입력은 원래 브라우저·
주소·포트에서 먼저 복구합니다. 개발 미리보기에도 `--host`를 추가할 수 있으며 기록은
실제 practice가 아닌 `build/web-preview/` 등에서 만듭니다.

## 검증과 발행

개인 기록은 테스트에 사용하지 않습니다. 소스 편집 후 버전을 올리고 아래를 실행합니다.

```sh
uv lock
uv run python -m unittest discover -s tests -v
uv run python review.py validate-curriculum
node --test tests/capture.test.mjs tests/i18n.test.mjs tests/score.test.mjs
# 합성 프로필·기록만 사용하는 수동 실제 연결 검사 (계정 사용량 발생)
uv run python tests/codex_smoke.py --run
```

Playwright 브라우저 검사는 [영문 문서](README.md#web-validation)를 참고합니다.
새 버전 소스를 커밋·태그한 후 발행합니다.

```sh
uv run python publish.py --ref v0.4.1
```

발행은 새 버전 활성화를 우선합니다. 호환 미완료 과제는 원래 조건을 유지하고 비호환은
사유와 함께 retired로 종료합니다. 원문·MIDI를 보존하며 실패나 스킵으로 처리하지
않습니다. generated 과제는 커리큘럼 목록과 무관하게 자체 형식 지원 여부로 판단합니다.
`--cache-only`는 활성화하지 않고 캐시만 준비합니다. 활성화 후 서버를 다시 시작합니다.

`practice/runtime.json`은 로컬 활성 핀이고 `.runtime/`은 재생성 가능한 Git 스냅샷
캐시입니다. 개인 CSV, 프로필, MIDI, 추천 맥락/결과, 번역 캐시, 메모와 백업은 커밋하지 않습니다.
서버를 중지하고 이 개인 자료와 runtime.json을 별도로 백업합니다. Git은 개인 자료의
백업이 아닙니다. MIDI 포맷·복구·실행기 설명은 [영문 문서](README.md)를 참고합니다.

공식 문서: [비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode),
[인증](https://learn.chatgpt.com/docs/auth), [app-server](https://learn.chatgpt.com/docs/app-server).
